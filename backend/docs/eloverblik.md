# ElOverblik Customer API integration

Verified against the [official Customer API Swagger](https://api.eloverblik.dk/customerapi/swagger/customerapi-v1.0/swagger.json) on 2026-10-08. The app uses the Customer API, never the ThirdParty API. A refresh token is exchanged at `GET /customerapi/api/token`; meter requests use the data-access token. The timeseries request body is `{ "meteringPoints": { "meteringPoint": ["18-digit-id"] } }` and `Actual` preserves native interval resolution. The provider permits at most 730 days per request; this integration uses 30-day chunks.

The connection starts disabled. An administrator creates a Customer API token in ElOverblik, saves it on the private Energy data setup page, then explicitly chooses a linked meter. The default meter scope is **household**. Selection enables six-hour polling. Selecting a *different* meter starts that meter's own 13-month backfill (coverage, cursor and recorded gaps are never inherited); re-selecting the same meter keeps its progress. Disconnect deletes the credential and stops polling while retaining interval and charge history; `POST /disconnect` with `{ "purgeHistory": true }` additionally deletes all imported intervals and charge snapshots/observations.

`eloverblik_intervals` stores UTC start/end, decimal kWh, quality, business type, unit-derived series identity and observed time. Only A04/A64 consumption with kWh units is normalized; generation is excluded. A02 missing quantities stay `NULL`; a measured zero stays zero. Consumers must resolve a single appropriate series and must not sum alternate aggregations or whole-household kWh into server kWh. iLO provides separate server power telemetry. Charge responses are versioned opaque admin-only snapshots; no present charge is retroactively asserted as an earlier tariff. The price engine must determine applicable components and unknown tax or VAT semantics separately.

## Failure handling

- **Retry-After** on 429/503 is honoured as delay-seconds or an HTTP-date, clamped to 24 hours, persisted (`retry_after_until`) so restarts and manual resyncs respect it.
- Other failures back off exponentially from 15 minutes up to 12 hours (`consecutive_failures`, `next_attempt_at`).
- A **backfill chunk** that fails three times for a period-specific reason (malformed/oversized response, upstream per-meter error, HTTP 5xx) is recorded in `skipped_ranges` and the backfill continues. Network, rate-limit and authorization failures never skip a chunk. A successful manual period resync (`POST /sync` with `{ "from": "YYYY-MM-DD", "to": "YYYY-MM-DD" }`, max 31 days) closes a recorded gap without moving the backfill cursor.
- **401/403 semantics:** a rejected refresh-token exchange means *reconnect required*. A 401 on a data call refreshes the access token and retries once. A 403 on a meter-scoped call — or a 401 that persists with a freshly issued token — means the selected meter is not authorized (*meter unauthorized*), not that the token expired. A response without the selected meter means *meter missing*.
- These three states set `attention_code`, stop all polling and token use until the owner pastes a new token or reselects the meter, and emit one deduplicated private `energy.meter_attention` notification (no meter ID, token or household data).
- A single unparseable quantity is stored as unknown (`NULL`, quality `invalid_value`) rather than rejecting the chunk; decimal commas and JSON numbers are accepted, extra decimals are rounded half-up to 6 places. Negative or non-numeric consumption is never coerced to zero. `P1D` periods follow Danish calendar days (23/25 hours on DST days). Metering point IDs delivered as JSON numbers are rejected because 18-digit IDs exceed safe integer precision.

## Charge observations

`eloverblik_charge_snapshots` stores each distinct charge payload once. `eloverblik_charge_observations` records the observed sequence: an unchanged payload extends the current observation's `last_observed_at`; a changed payload — including a return to an earlier version (A → B → A) — starts a new observation. Observation times are when the source reported the content, not tariff effective dates.

No production meter connection has been tested. Tests use sanitized fake envelopes (`src/testUtils/eloverblikFixtures.ts`) covering the full token → meter → backfill → refresh workflow, expiry, revocation, credential replacement mid-import, unauthorized/missing meters, 429/503, chunk skipping and restart idempotency. ElOverblik can lag behind real time, so the latest interval timestamp is shown explicitly. Upstream bearer tokens and private response fields must never be logged or sent to members.
